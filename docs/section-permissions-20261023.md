# Доработки реестра по встрече 23.10.2026

AC-1: независимые права на финансы, поля и содержимое по фактическому разделу документа, с серверной защитой всех путей чтения и изменения.
AC-2: Product Manager сохраняет sales и назначения; видит суммы клиентских документов, не видит суммы и содержимое поставщика.
AC-3: отображаемые названия ролей изменяемы, защищённые права администратора неизменны.
AC-4: настройки показывают поля выбранного раздела, библиотека включает встроенные и дополнительные поля без дублирования.
AC-5: единый денежный формат во всех вводах и представлениях, ноль отличим от отсутствующего значения, старые значения не переписываются.
AC-6: расследовать два договора без удаления; объяснить уникальность номера по типу и компании и проверить конкурирующие запросы.
AC-7: тесты, browser evidence, выпуск с откатом и отчёт.

NG-1: не менять счета, обмен 1С, нумерацию, исходные документы и существующие незакоммиченные изменения.
NG-2: не заменять live Marketplace runtime устаревшим исходником; накладывать проверяемое изменение на точный baseline.
NG-3: не включать строгую уникальность автоматически и не отмечать клиентскую приёмку.

## Результат

Правила `permissions.bySection[sectionCode]` содержат необязательные `finance`, `content` и `hiddenFields`. Явное правило фактического раздела имеет приоритет; отсутствие сохраняет прежнюю политику. `hiddenFields: []` явно очищает наследуемый список для раздела. Администратор сохраняет полный доступ.

Для `sales` имя изменено на Product Manager: финансы клиентского раздела доступны, финансы и содержимое поставщика закрыты. Сумма и валюта остаются одними и теми же реквизитами. Назначения пользователей и остальные права сохранены.

На сервере правила применяются к карточкам, спискам, истории, дополнительным полям, фильтрам, итогам, экспорту и выдаче доступа к файлам. Фильтрация по скрытым значениям отклоняется, чтобы результат поиска не раскрывал их косвенно. В интерфейсе выбор раздела сохраняет черновики остальных разделов. Системной роли можно менять имя отдельным PATCH; защищённые права администратора этим маршрутом изменить нельзя.

Библиотека показывает встроенные реквизиты и существующие дополнительные поля с поиском и областями использования. Встроенные поля обозначены отдельно и повторно не создаются. Денежный формат — `1 234 567,89`, ноль — `0,00`; историческая дополнительная точность сохраняется, например `12,3456`.

## Повторное создание

Проверены два указанных заказчиком договора: две карточки, один автор, одинаковые основные реквизиты, интервал 3,693 секунды, два вложения и два файла Диска. Обе карточки созданы вручную, а не синхронизацией. История подтверждает два самостоятельных завершённых создания; она не позволяет достоверно отличить повторное нажатие от намеренного повторного ввода. Совпадение содержимого файлов не утверждается.

Существующая немедленная блокировка повторного создания и предупреждение о совпадающем номере сохранены и проверены в браузере. Строгая уникальность включается отдельно: при двух одновременных завершениях один запрос проходит, второй получает конфликт. Существующие документы не удалялись и не объединялись.

Настройка называется «Уникальный номер в пределах типа и компании». Она запрещает повторный номер внутри одной комбинации типа и компании при включённом строгом режиме; сама по себе похожесть названий или одинаковый файл этой проверкой не определяется. Автоматического включения не было.

- 8 проверок нового runtime: один тип в двух разделах, API, история, фильтры, XLSX, файлы, суммы, отсутствие правил, точность и конкурирующая уникальность.
- 8 проверок прежнего runtime: CRM ACL, связи, создание и обязательность файлов — успешно.
- 7 проверок административных маршрутов: переименование без потери назначений, защищённые права, preview/commit/version/audit, назначение и отзыв администратора — успешно.
- 7 браузерных проверок опубликованного интерфейса с синтетическим API — успешно, ошибок JavaScript нет. Включают черновики разделов, библиотеку, формат денег, отмену дубля и одновременный повтор создания.

## Выпуск и откат

Развёрнутая версия Marketplace содержит изменения, которых ещё нет в исходниках backend этой ветки. Поэтому полный результат компиляции backend не развёртывался. `build-section-runtime.mjs` накладывает точечные изменения только на модули с проверенными SHA256 из `runtime-hashes.json`; остальные модули наследуются от действующего образа, включая административные назначения.

Релиз: `/opt/reestr-docs/releases/section-permissions-20261023`. Readiness — `ready`, опубликованный HTML совпадает с проверенным, соседние контейнеры не изменились. После применения настроек конфигурация версии 16. Откат: `python3 /opt/reestr-docs/releases/section-permissions-20261023/deploy.py rollback`. Снимки окружения и настроек хранятся только на сервере с правами 0600. Откат настроек проверяет версию, чтобы не затереть последующие изменения администратора.

Для браузера: установить Playwright и Chrome либо задать `PLAYWRIGHT_MODULE`, затем выполнить `REGISTRY_FRONTEND_URL=<URL> node scripts/verify-section-browser.mjs`.
