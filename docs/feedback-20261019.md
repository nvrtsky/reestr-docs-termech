## Что установлено по приложенным скриншотам

Первые пять изображений показывают один сетевой симптом: Bitrix не соединяется с доменом приложения, и прямое открытие заканчивается `ERR_TIMED_OUT`. Это происходит до загрузки приложения. Исправления форм и авторизации сами по себе такой таймаут не устраняют. На момент проверки DNS A указывает на 79.174.77.28, записи AAAA нет, HTTPS отвечает, контейнер backend не перезапускался и не был остановлен OOM. Причина сбоя в сети пользователя не воспроизведена.

Проверка записи документа `f187076a-2f1a-4134-a52b-27c1aadb57e2` из сделки 1588 подтвердила сохранённое текущее вложение PDF: Bitrix Disk ID 57491, размер 421016 байт. Само наличие записи не подтверждает доступ конкретного сотрудника к файлу. Для этого требуется открытие из его авторизованной сессии. Данные и права документа не менялись.

## Проверка после выпуска

1. Открыть реестр из сделки и прямой ссылкой в той сети, где возникал таймаут. При повторении запустить диагностику там и сравнить время и DNS; отчёт не содержит токенов.
2. В сделке 1588 открыть указанный документ, проверить «Открыть» и «Скачать» текущего PDF под учётной записью сотрудника.
3. На ноутбуке открыть добавление документа, прокрутить поля тачпадом до нижних кнопок. Синтетический wheel-тест подтверждён; физический Lenovo и реальная сессия Bitrix ещё не проверены.
4. Открыть существующую роль: отмеченные поля видимы, снятые скрыты. Смена двух отметок обратно сохраняет прежний hiddenFields. Без необходимости не менять реальные права.
