# Граница приложений КП и Реестра документов

Status: active  
Date: 2026-09-23

## Решение

«Реестр документов» является самостоятельным многопортальным приложением
Маркетплейса Bitrix24. Конструктор коммерческих предложений — отдельное
локальное приложение заказчика. Они не разделяют runtime, базу, OAuth или
процесс выпуска.

| Область | Реестр документов | Конструктор КП |
| --- | --- | --- |
| Production-домен | `reestr.navrotsky.ru` | `docs.thermech.ru` |
| Инфраструктура | Сервер разработчика | VPS заказчика `200.169.189.86` |
| Модель Bitrix24 | Marketplace, multi-tenant | Локальное приложение одного портала |
| Placements | `LEFT_MENU`, `CRM_DEAL_DETAIL_TAB`, `CRM_COMPANY_DETAIL_TAB` | `CRM_DEAL_DETAIL_TAB` |
| Данные | Общая физическая БД с обязательной изоляцией tenant по проверенной установке | Отдельная БД заказчика |

## Первый клиент

- `thermech.bitrix24.ru` устанавливает тестовую Marketplace-версию до
  публикации приложения.
- Tenant создаётся чистым. Документы, роли и настройки старого локального
  Реестра не мигрируют.
- После успешной приёмки левое меню и вкладки сделки/компании старое локальное
  приложение удаляется сразу, без параллельного периода эксплуатации.
- Секреты старого локального приложения после удаления не используются.
- После пилота приложение отправляется на модерацию Маркетплейса.

## Изоляция и владение

- Каждая установка идентифицируется проверенными `member_id` и доменом портала.
- Документы, настройки, роли, OAuth-токены и папка Bitrix Disk изолированы по
  tenant.
- Реестр не разворачивается на VPS клиента и не использует домен
  `docs.thermech.ru`.
- Конструктор КП не входит в этот репозиторий и не публикуется вместе с
  Реестром.

## Порядок выпуска

1. Выпустить Marketplace-версию на `reestr.navrotsky.ru` с чистой production-БД.
2. Провести техническую проверку на тестовом портале разработчика.
3. Установить тестовую версию в `thermech.bitrix24.ru` как первого клиента.
4. Проверить чистую и повторную установку, OAuth refresh, три placement,
   права, Bitrix Disk, карантин и резервное восстановление.
5. Сразу после приёмки удалить старое локальное приложение Реестра.
6. Отправить проверенную версию на модерацию Маркетплейса.

## Запрещённые отклонения

- Не объединять Реестр и КП в одно приложение или одну базу.
- Не переносить Реестр на сервер заказчика.
- Не использовать credentials локального приложения для Marketplace.
- Не импортировать старую локальную базу Реестра первому клиенту.
- Не оставлять старый и Marketplace-Реестр активными одновременно после
  приёмки.
