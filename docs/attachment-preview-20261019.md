После загрузки документа кнопка «Открыть» ведёт на страницу Bitrix Disk с 404. Нужен предпросмотр внутри Реестра для текущих вложений и истории файлов.

AC-1: «Открыть» для файла показывает доступный с клавиатуры просмотрщик внутри Реестра без перехода на DETAIL_URL. Для внешних ссылок сохраняется открытие ссылки.
AC-2: PDF, PNG/JPEG/GIF/WebP/BMP, текст/CSV доступны для просмотра; DOC/DOCX/ODT/RTF, XLS/XLSX/ODS, PPT/PPTX/ODP преобразуются в PDF локально. Для неподдерживаемого, повреждённого или слишком большого файла показаны понятное состояние и скачивание оригинала.
AC-3: Доступ к содержимому требует проверенной сессии и существующих прав на документ и Disk-файл. Токены не попадают в URL приложения или журналы. Файлы не передаются публичным сторонним просмотрщикам; временные файлы удаляются.
AC-4: Есть имя файла, загрузка, ошибка/повтор, закрытие, скачивание; быстрые переключения и закрытие отменяют/игнорируют предыдущую загрузку. Работают текущие вложения и история, узкий экран и iframe Bitrix.
AC-5: typecheck/build, тесты доступа/форматов/ошибок и браузерные доказательства. Выпуск поверх точных действующих образов с проверкой и откатом; права, БД и функции предыдущих исправлений сохранены.

Скриншот: https://skr.sh/se3LFuVsbUI (последний символ — заглавная I). На нём открыта страница Bitrix `/docs/file/…`, заканчивающаяся на путь папки; Bitrix показывает 404. Нельзя считать это доказательством отсутствия самого вложения.

Реализация: модальный просмотрщик на текущей странице, blob без REST-токенов в URL приложения; оригинал скачивается по свежему DOWNLOAD_URL. `/attachments/:attachmentId/preview` заново вызывает существующий `getAccess` с пользовательской сессией, загружает содержимое, проверяет формат/размер и при необходимости преобразует офисный файл в PDF. Публичные внешние просмотрщики не используются. Лимит предпросмотра — 25 МБ (текст — 2 МБ); одна конвертация одновременно, отдельный временный профиль, таймаут и очистка. Конвертер не наследует секреты backend, макросы отключены максимальным уровнем безопасности, HTTP(S)-прокси конвертера указывает на закрытый локальный порт для блокировки внешних ресурсов.

База backend на сервере новее ветки: она содержит доступ к динамическим файловым полям и копии вложений. Поэтому скрипт выпуска проверяет SHA-256 точного рабочего attachments.service.js и меняет только приоритет URL и добавление имени/размера. Исходные проверки полей, прав, истории и загрузки сохраняются. Router до изменений совпадал с сервером по SHA-256. В frontend накладывается следующий проверяемый overlay поверх предыдущего выпуска; новый React shell не выкладывается.

Проверено локально: typecheck, build, 12 тестов форматов/URL/размеров/доступа, 9 групп браузерных сценариев Chrome. Скриншоты и отчёт — `docs/evidence/attachment-preview-20261019/`. Использованы синтетические API-ответы и файлы. Проверки реальной конвертации LibreOffice и полного доступа к файлу сотрудника в Bitrix пока не выполнены.
