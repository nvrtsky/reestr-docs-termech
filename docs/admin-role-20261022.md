# Стандартная роль администратора реестра

Задача: https://github.com/nvrtsky/reestr-docs-termech/issues/41

В «Настройки → Роли и доступ → Назначение пользователей» теперь можно выбрать стандартную роль **Администратор** для обычного сотрудника. Она открывает настройки реестра и предусмотренный этой ролью доступ к документам. Пользовательская роль «Администратор приложения» автоматически не меняется: совпадение названия не является назначением стандартной роли.

После выбора нажмите «Сохранить назначения», проверьте изменения и нажмите «Применить». Сотруднику нужно обновить приложение. Администратор Bitrix24 сохраняет автоматический доступ; роль приложения не даёт прав администратора портала.

AC-1: стандартная роль доступна в списке пользователей, оба API назначения принимают её. Назначение администратора подразделению остаётся закрытым.
AC-2: доступ к настройкам проверен на действующей сессии; отзыв сбрасывает кэш, повторная проверка внутри транзакции защищает от сохранения после отзыва.
AC-3: идентичность администратора портала проверяется отдельно от роли приложения. Управляющий настройками не может назначить или отозвать администратора, но может сохранять другие назначения, оставляя текущих администраторов без изменений.
AC-4: три браузерных сценария со скриншотами на синтетических сотрудниках, три теста исходного backend, шесть групп интеграционных проверок точных production-модулей на отдельной PostgreSQL, девять существующих регрессий конфигурации и сессий. Typecheck и build прошли.

NG-1/2: реальные назначения сотрудников не изменялись. Проверка входа конкретного сотрудника в рабочем Bitrix24 не выполнялась, поскольку пользователь не указал, кому назначить роль.
NG-3: работа выполнена в отдельном worktree поверх выпущенных исправлений вложений. Незакоммиченные изменения исходной рабочей папки сохранены.

Рабочий backend содержит дополнительные механизмы Marketplace, подтверждения настроек, аудита и блокировки конфигурации, отсутствующие в старой базе TS. Для выпуска использован `scripts/registry-admin-runtime-overlay.mjs`: он проверяет SHA-256 трёх текущих модулей и применяет только изменения назначения/проверки роли. Полные рабочие модули проверены на изолированной БД. Существующие защиты и конфигурация сохранены. Миграции и изменение рабочих данных не требуются.

Выпуск 22.10.2026: frontend/backend `admin-role-20261022`, readiness `ready`. Опубликованный HTML побайтно совпадает с проверенным. Другие контейнеры не пересоздавались. Образы до изменения и приватные конфигурации сохранены на сервере. Откат: `python3 /opt/reestr-docs/releases/admin-role-20261022/deploy.py rollback`.
